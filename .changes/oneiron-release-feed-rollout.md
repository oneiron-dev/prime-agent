- `scripts/oneiron/side_by_side.py package` turns a `scripts/package_release.py` build into a versioned side-by-side release (`prime-agent-<base>-oneiron.YYYYMMDD.N-<platform>.tar.gz`, `SHA256SUMS`, `manifest.json`, feed `latest.json`/`stable`) for linux-x64 and darwin-arm64. The tarball is deterministic, and a published platform is never overwritten.
- `side_by_side.py rollout` installs a feed release only after its sums verify and the new version passes a probe. It refuses while the side-by-side Rust daemon has live sessions, and records everything in `ACTIVATION-RECEIPT.json`. `rollback` returns to the previous (or a named) installed version with a `ROLLBACK-RECEIPT.json`. `status` shows installed versions, pointers, receipts and the feed. The operator procedure is in `docs/oneiron/RELEASE.md` and `docs/oneiron/ROLLBACK.md`.
- `rollback` only selects a version whose whole installed payload matches a receipt showing it once ran as current, `rollout` reuses a left-behind install only when its payload equals the release, and both hold the install lock for the whole run. Re-running `package` on an already published release can now promote it.
- Rollout and rollback re-check the install right before the swap, journal their receipts phase by phase (a crash leaves `running` and the phase), and record any error. Rolling out the current version again re-verifies it. The `prime-agent-rs` launcher keeps Python bytecode out of the install (`PYTHONPYCACHEPREFIX`), and Linux packages always carry their split-debug decoder. Rollout and rollback only ever send the Rust supervisor `list`; a supervisor of another release is reported in the receipt, never stopped.
