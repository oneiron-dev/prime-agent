- OpenAI Responses models that opt in with `compat.supportsWebSocket` (or any Responses model under the `websocket`/`websocket-cached` transport setting) now stream over a WebSocket: one reused connection per session, follow-up requests send only the new input after a successful response, and the request falls back to SSE only if the socket fails before the first event.
- A WebSocket that drops mid-response is reported as a connection failure (`websocket_closed`, `websocket_error`, ...) and retried by the session on a fresh connection with the full request; provider error frames, including the CPA gateway's nested envelope, keep their own verdict with credentials redacted.
- The `transport` setting now takes effect (`websocket` used to load as `auto`, and `set_transport` saved `websocket-cached` as `websocket`), survives model switches and provider failover, and closing a session cancels its in-flight WebSocket requests.
- Provider retries reset after every successful model call inside a tool-using turn, retry waits never undercut a server-requested `Retry-After`, and compaction summaries carry the session id and retry transient failures.
