- `--mode json --json-event-profile factory-completed` (or `=factory-completed`) streams the completed session events only: the progressive `message_update` and `tool_execution_update` snapshots are left out and the session header carries `"jsonEventProfile": "factory-completed"`. `--json-event-profile all` is the default stream; the flag requires an explicit `--mode json`.
- `--no-skills`, `--no-prompt-templates` and `--no-context-files` now take effect in print and json runs: discovered skills, prompt templates and `AGENTS.md`/`CLAUDE.md` context are left out of the session (explicit `--skill`/`--prompt-template` paths still load).
- `--daemon-hosted` runs a print or json session inside the daemon, so another terminal can attach to it while it runs; the run streams the same output, `-c` and `--resume` reuse the worker that already hosts the session, and exiting or a signal only detaches. It cannot be combined with `--no-session`, and for now also refuses `--no-skills`, `--no-prompt-templates`, `--no-context-files`, `--goal`, `--offline`, `--fork`, and `--mode rpc|acp`.
